A self-healing web-scraper factory, operated by Port

Scrapers rot. This treats it as an on-call problem — and lets robots run the rotation.

The Scraper Factory reads ~12 days of TV-guide data across Philo, YouTube TV, and Sling, ranks the top 10 shows and top 10 movies by TMDB popularity, and gives you one click to record each title on Philo. Port schedules the scrapes and reacts to failures; when a scraper breaks, a repair loop fixes it — but a deterministic inspector with a frozen checklist decides whether the fix is real.

Explain it like I'm 10

Imagine a robot factory that reads the TV guide every morning, picks the twenty best things to watch, and puts them on a poster you can tap. A boss-robot (Port) rings the bell each day so the reading-robots start on time. Sometimes the TV-guide website changes its shape and a reading-robot gets confused, so another robot tries to fix it. But before anyone trusts the fix, a strict inspector checks the repaired robot against an answer sheet that never changes. No matching answer sheet? No promotion — the robot goes to the "needs a grown-up" pile.

⏰Ring the bellPort starts the day's scrape on a schedule
📺ReadRobots read the guide, one channel page at a time
🏆Pick & showScore every title; put the top 10 shows + 10 movies on the poster
🔧FixWhen a robot breaks, another robot repairs it
🕵️InspectA plain checklist decides if the fix is real

The one rule: the fixer can be a clever robot, but the inspector is a plain checklist you can trust every single time. Judgment goes to the agents. Proof stays deterministic.

All three share one rule: an agent decides what broke or what to build; plain deterministic code — a fixture diff, a CI run — decides whether it's real. The self-heal loop has even been proven on the unhappy path: a bad repair was correctly rejected by the verifier and escalated to a human. That rejection is the system working.

The thesis, for grown-ups

Web scrapers are fragile by nature: a guide site ships a redesign, selectors stop matching, and the data either stops arriving or — worse — arrives subtly wrong. The Scraper Factory treats that as a reliability problem with an on-call rotation. Scrapers are catalogued services with health states. Every run is traced. Drift is an alert. Repair is an automated loop that must prove itself against a frozen fixture before its output is trusted, and escalates to a human when it can't. Built on Port (control plane + operator), Bright Data Scraper Studio (scraping + self-healing), SigNoz (traces, metrics, logs), and TMDB (the ranking signal).
