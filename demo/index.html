The Scraper Factory

Scrapers as catalogued services: every run traced, drift is an alert, repair is an automated loop gated by a frozen fixture. Judgment goes to the agent. Proof stays deterministic.

The fetch/extract split — why runs show a relay URL

→

Extract

→
collector runchannel-schedule
→
program rowstitle · times · category
Why: Bright Data's policy blocks streaming-media domains for collector runs (confirmed by their support engineer, who endorsed this exact pattern). So the pipeline uses two Bright Data products: the Web Unlocker fetches the live page, the Scraper Studio collector extracts and self-heals. Two wins fall out for free: the collector always tries direct first, so if policy changes the relay disappears on its own — and every scrape's input HTML is archived, so a drift investigation replays the exact bytes the collector saw.

Port — the control plane, in detail

1
Context Lake — the catalog

Five blueprints, all provisioned by make bootstrap: scraper (health · verify_status · prompt), scrape_run (rows · drift · clickable trace_url), heal_event (the repair audit), ranked_title (the product), data_source (operator briefs).

2
Workflows — the drift automation

invoke_healer_on_drift: ENTITY_UPDATED on scraper, JQ-gated on health == "drifting" → webhook to the factory's public /heal. Plus request_data_source: an operator brief in, a verified scraper out.

3
AI agents

The Port-native Triage agent authors drift descriptions; a Claude coding agent provisioned this entire control plane through the API — Port as a platform consumed by agents, not just humans.

4
Governance — the scorecard

Scraper reliability: Basic → Bronze (verified today) → Silver (verify passing) → Gold (healthy + verified). Computed from properties the pipeline writes — trust as data, not claims.

5
Interface Builder — Factory Operator

One dashboard: scrapers-by-health pie, heal-event table, ranked-titles table with record links, architecture note, and the SigNoz dashboard iframe.

⚙
All of it is code

scripts/bootstrap_port.py — idempotent, re-runnable, no UI clicks. The API shapes were validated against the live EU instance (api.getport.io).
