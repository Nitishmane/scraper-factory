The agent workforce

The factory is staffed by a mix of robots (agents and code) and humans, each with a narrow job. The trick isn't handing everything to an LLM — it's deciding, role by role, where judgment belongs and where a machine you can trust deterministically has to stand guard.

It's a workshop of little workers — some are robots, some are people — and each one has exactly one job.

Four of the Port AI agents above (Triage, Heal Explainer, On-Call Assistant, Catalog Coverage) are the factory's own; the Port workspace also carries stock demo agents from the Port quickstart. Only the four listed here are wired into this system.

Every Port → factory call (the Runner, Healer trigger, and Intake webhooks) is a token-gated POST: a shared secret FACTORY_WEBHOOK_TOKEN baked into the provisioned webhook URLs, constant-time compared, with a bare call rejected 401. So only the operator's own Port org can drive the workforce.

The doctrine: judgment to agents, proof stays deterministic

A clever robot can guess the fix, but a plain checklist — not a robot — decides if it's really fixed.

🧠 Judgment → agents

Deciding what broke, whether a repair is worth attempting, how to phrase the symptom, what feature to build — these are fuzzy, context-heavy calls. That's exactly where LLM agents earn their keep: Triage reasons over history, the Builder writes code, the Healer re-prompts the scraper.

✅ Proof → deterministic code

Deciding whether a fix is real is not fuzzy. The Verifier diffs against a frozen fixture; CI runs pytest, tsc, and next build. No LLM is allowed at a promotion gate, because a gate you can't trust deterministically isn't a gate. The fixture is the only promotion gate in the heal loop.

Why the Builder runs locally

🔒

No Anthropic credentials leave the operator's machine.

The Planner + Builder is headless Claude Code running locally, behind the FastAPI /feature endpoint — not in a cloud runner. It edits a scratch clone with file tools only; deterministic code (in agents/builder.py) handles branch, commit, push, and PR, which also guarantees the PR-body contract (Requirement: req_<id>) that the deploy workflow parses on merge. GitHub Actions only ever runs no-AI steps: the CI gate and the Vercel deploy. This was a deliberate operator decision — the model's API key stays on the laptop, and the cloud sees only code and test results.

A cloud-runner variant of the builder was built and then deliberately removed — running it would have shipped an Anthropic API key to GitHub Actions. The local builder is the only builder; the only workflows left in .github/workflows/ are ci.yml and deploy.yml, both no-AI.
